# План: приложения и «блоки» диагностики

Состояние на 2026-11-02 (ветка `master`, сайт 2.16). Продолжение в другой сессии — всё нужное здесь.

## Зачем

Для части диагнозов перечень диагностики стоит не в тексте главы, а в приложении к протоколу,
а текст или таблица только ссылается на него. Сейчас такие ссылки не раскрываются: ответ —
«требует ручной проверки» или неполный перечень. Пример из реальных вопросов оператора
(`eval/operator_pending.md`): «лейомиома», «миома» → D25 → «ТРЕБУЕТ РУЧНОЙ ПРОВЕРКИ».

Две разные задачи:

- **A. Блоки акушерского протокола** — один документ, но очень важный для страховщика (вся
  гинекология и акушерство взрослых) и с самым большим числом ссылок.
- **B. «… согласно приложению N»** в диагностических пунктах — много документов, ссылка на
  приложение-таблицу или приложение-текст целиком.

## A. Блоки (акушерство и гинекология, 2026)

Документ: `protocols/Акушерство, гинекология/КП_акушерство и гинекология (взрослые) в ред. пост. МЗ РБ от 18.06.2026 №73.pdf`
(kind `table`, 101 табличная страница). В корпусе определения блоков есть ещё только в одном
документе (`Аллергология…/КП_Диагностика_и_лечение_детей_с_онкологическими_и_гематоло…`,
блоки А–В, 1 ссылка), ссылки на блоки без определений — ещё в двух акушерских
(«…при родах…» 2026 №73 — 12 ссылок, «…послеоперационным рубцом…» — 8): они ссылаются на
блоки *основного* акушерского протокола.

### Как устроено

**Приложение 1** «Диагностика во время беременности, родов, в послеродовом периоде, при
гинекологических заболеваниях» (стр. 2–5 PDF), обычный текст:

```
1. Клиническое обследование беременной (далее – Блок А).
1.1. Обязательное: анамнез…; общий осмотр; измерение АД…; …
1.2. Дополнительная диагностика и консультации врачей-специалистов по показаниям.
2. Клиническое обследование (далее – Блок Б) женщины с гинекологическими заболеваниями …
2.1. Обязательное: …   2.2. Дополнительная …
3. Специальное акушерское (гинекологическое) обследование (далее – Блок В): осмотр в зеркалах; …
4. Лабораторное исследование (кроме инфекций) … (далее – Блок Г). 4.1. Обязательная диагностика: ОАК…; 4.2. Дополнительное …: MCV…; ферритин…; ТТГ…
5. Функционально-инструментальное исследование беременной (далее – Блок Д). 5.1 / 5.2
6. … гинекологической пациентки (далее – Блок Е). 6.1. Обязательная: ЭКГ; УЗИ ОМТ. 6.2. Дополнительная: кольпоскопия, …, маммография, …
7. Исследование на инфекции при беременности (далее – Блок Ж). 7.1 / 7.2
8. … (далее – Блок З).
```

Пункты — по одному на строку, «;» в конце. У каждого блока статусы «обязательная» и
«дополнительная (по показаниям)». У блока В подпунктов нет: всё обязательное, кроме помеченного
«(по показаниям)».

**Приложения 3–4** («Диагностика и лечение гинекологических заболеваний…»): таблицы 1…N по
группам МКБ («Болезни молочной железы (шифр по МКБ-10 N60)», «Воспалительные болезни … N70–N77»,
«Новообразования … D06–D07, D25–D28» …). Шапка: `Объем оказания медицинской помощи | Диагностика* |
Лечение** | Средняя длительность лечения. Тактика ведения`, сноска `* Объем диагностических
обследований согласно блокам, приведенным в приложении 1`. **Колонки «наименование» нет**:
нозология — строка на всю ширину («D25.0 Подслизистая лейомиома матки», или несколько кодов
подряд: «D25.1 … D25.2 … D25.9 …»), ниже — ячейка «Диагностика*»:

```
Блок Б.
Блок В.
Блок Г.
Блок Е.
Исследование на сифилис, ВИЧ, гепатиты В и С.
Гистероскопия + РДВ по показаниям.
Гистологическое исследование.
Консультация врача-гематолога по медицинским показаниям, а именно: …
```

Встречаются: «Блок Г 1/5-10.» (номера пунктов блока? — **не выяснено**, единичный случай,
таблица 2, N70.0), «Согласно таблице 9 настоящего приложения» (ссылка на другую таблицу того же
приложения, 5 раз), пункты «… по показаниям».

Почему сейчас не работает: `table_extract.roles_of` требует колонку имени (`name`) —
её нет, роль name не находится → таблица пропускается. Из этого документа извлечено всего 4
строки. Текст приложения 1 в KB есть (раздел `table_free`), но привязан к коду протокола, а не
к блоку, и в ответе по D25 не участвует.

### Что сделать

1. **Разбор определений блоков** (новая функция, например `kb_build.parse_blocks(doc)`): по
   абзацам документа найти `(далее – Блок X)` → номер пункта N → подпункты `N.1` (статус по
   словам «обязательн» / «дополнительн … по показаниям», как `header_level`) → пункты-строки до
   следующего `N+1.`. Результат: `{"А": {"page": 2, "title": "Клиническое обследование
   беременной", "mandatory": [...], "additional": [...]}, …}`. Блоки без подпунктов (В) —
   `listed` / по пометке «(по показаниям)». Хранить в `documents[doc_id]["blocks"]`.
   Документы, которые ссылаются на блоки, но не определяют их, берут блоки основного акушерского
   протокола (найти по `(далее – Блок` в корпусе; связь — явная таблица в `data/`, не эвристика).
2. **Таблицы с нозологией строкой на всю ширину** в `table_extract.py`: если в шапке нет колонки
   имени, но есть колонка диагностики — строка, у которой одна непустая ячейка на всю ширину и
   она начинается с кода МКБ (или несколько строк кодов подряд), открывает нозологию; коды
   из неё. Роль колонки «Диагностика*» без «обязательн / дополнительн» → `listed`. Проверить
   на всех документах (сравнение строк старый/новый, как в прошлый раз — скрипты ниже).
3. **Раскрытие блоков** в `kb_build` при сборке секций табличных строк: пункт ячейки
   «Блок Б.» → пункты блока Б со статусами блока (обязательная / дополнительная), с цитатой
   и страницей **определения блока** (приложение 1), а в заголовке — откуда ссылка
   («Таблица, «D25.0 …», диагностика: Блок Б — Клиническое обследование…»). Остальные пункты
   ячейки («Гистологическое исследование.») — `listed` (статус не указан) или `additional`, если
   «по показаниям». «Блок Г 1/5-10» — пока раскрывать весь блок с пометкой «(частично: 1/5-10)»
   до выяснения смысла. «Согласно таблице N» — ссылка на строку другой таблицы: отложить.
4. **Ответ / сайт**: в цитате видно, что пункт пришёл из блока («Блок Е, п. 6.2: маммография»),
   ссылка `#page=` — на страницу блока. `kb_web` — `VERSION` +1.
5. **Проверка**: в `eval/operator.jsonl` добавить «лейомиома», «лейомиома перечень» (D25 — имя
   МКБ, без медицинского решения) с `"level": "list"`; кейсы вида «лейомиома, разрешена ли
   маммография» (ожидание: дополнительная, через Блок Е) — только после проверки экспертом
   (`operator_pending.md`). Все eval-наборы + `kb_probe.py` — как обычно.

Оценка: 1–3 — день работы; основной риск — разбор пунктов блоков (переносы, «;» внутри скобок).

## B. «… согласно приложению N»

Абзацев «диагност… согласно / в соответствии с / указанн… в / приведенн… в приложении N»: 363
в 122 документах. Значительная часть — **шум**: преамбула постановления («клинический протокол …
согласно приложению 8 к настоящему приказу»), ссылки на шкалы и алгоритмы. Полезные — пункты вида

- «8. Обязательные диагностические исследования при лечении травм … установлены согласно приложению 1.» (травматология 02, 04)
- «9. Диагностические исследования, проводимые пациентам с ФП и (или) ТП … установлены согласно приложению 1.» (кардиология КП4, КП3, КП5)
- «… ежегодно проходят обязательные и дополнительные (по показаниям) инструментальные методы обследования согласно приложению 4.» (диализ)

### Что сделать

1. **Границы приложений** в `protocol_parser.py`: заголовок «Приложение N / к клиническому
   протоколу «…»» (правый край, несколько строк) → `appendices: [{no, title, page, page_end}]`
   в `parsed/docs/*.json`. Сейчас текст приложений попадает в последнюю главу.
2. **Связь пункт → приложение** в `kb_build`: пункт-заголовок со статусом (`header_level`:
   обязательные / дополнительные / диагностические исследования) и «согласно приложению N» без
   собственных пунктов → пункты приложения N получают этот статус и коды главы пункта:
   - приложение-таблица: строки `table_extract` на страницах приложения; строки **без кода МКБ**
     (сейчас отбрасываются — графики обследований, таблицы по уровням оказания помощи) берут
     коды главы-источника ссылки;
   - приложение-текст: списки, как в главах.
   Фильтр шума: ссылка «к настоящему приказу / постановлению» — не наша.
3. **Проверка**: сначала отчёт по 122 документам (сколько ссылок связалось, сколько пунктов
   добавилось), выборка глазами, затем eval + пробы.

Это же закрывает пункт TODO «таблицы без кода МКБ-10» (ТБ, ВИЧ, диализ): их строки привязываются
к главе, которая на них ссылается.
